# 人工复核工作流（方向一验收项）

- 导出：`tools/make_review.py` 把项目 JSON 转成复核 CSV
- 回填：`tools/apply_review.py` 读取人工结论并写回 JSON
- 实现：`src/ggai/review.py`

## 一、CSV 列

| 列 | 说明 |
|---|---|
| 序号 | 事件在项目中的序号（1 起） |
| 时间s / 类型 / 说话人 / 文本 / 置信度 | 自动填写，供复核参考 |
| 标记 | 自动标出的可疑项（首尾噪声/说话人可疑/文本过短/无证据） |
| 证据帧 | 对应截图路径 |
| 人工结论 | `confirmed` / `corrected` / `rejected`，留空=跳过 |
| 修正文本 | corrected 时填写 |
| 修正说话人 | corrected 时可填 |
| 复核备注 | 自由文本 |

## 二、回填规则

- `confirmed`：只改 review 状态；
- `corrected`：写入修正文本/说话人，`review.diff` 保留修改前后；
- `rejected`：标记驳回，不改内容；
- 序号越界、结论非法、corrected 无修改 → 计入 errors，不写入；
- 回填后强制协议校验，失败则拒绝输出。

## 三、演示（P002 v7，196 条）

导出复核 CSV 后，人工修改 3 行：

| 序号 | 结论 | 内容 |
|---|---|---|
| 1 | confirmed | 任务事件，无修改 |
| 2 | rejected | 备注「非对白/噪声」 |
| 172 | corrected | 文本改为「你们好，你们好，我是卡齐娜，「乌沙博蒂」的卡齐娜。」，说话人改为卡齐娜 |

回填结果：

```
rows=196  confirmed=1  corrected=1  rejected=1  skipped=193  errors=0
```

修正事件保留了完整 diff：

```json
{"before": {"text": "…「乌沙博蒂了的卡齐娜", "speaker": "沙博蒂"},
 "after":  {"text": "…「乌沙博蒂」的卡齐娜。", "speaker": "卡齐娜"}}
```

## 四、复核后的指标变化（30 条金标准）

| 指标 | 复核前 | 复核后 |
|---|---|---|
| 完全一致 | 66.7% | **70.0%** |
| 字符相似度 | 0.950 | **0.953** |
| 说话人准确率 | 93.3% | **96.7%** |
| 时间误差 | 0.02s | 0.02s |

说明人工修正确实能提升指标，也说明当前自动抽取仍有明确可改进点。

## 五、限制

- 目前是 CSV 工作流，没有图形界面；
- 单人复核，没有多人与冲突解决；
- 修改记录保存在事件 `review.diff` 中，未做版本库级历史；
- 复核后的项目仍需重新导出/入库才会进入下游。
