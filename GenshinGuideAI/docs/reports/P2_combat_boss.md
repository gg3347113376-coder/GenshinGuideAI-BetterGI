# Boss 战识别：模板匹配 + 时序过滤（方向一缺口进展）

- 日期：2026-11-07
- 模块：`src/ggai/combat.py`
- 工具：`tools/boss_bar_detect.py`、`tools/attach_combat.py`
- 模板：`data/templates/boss_cap.png`（Boss 血条左端盖，44×26）

## 一、方法

1. 取顶部带状区域（x 450–1450、y 40–200，按分辨率缩放）；
2. 用「Boss 血条左端箭头盖」模板做 3 尺度（0.95/1.0/1.05）TM_CCOEFF_NORMED 匹配；
3. 分数 ≥ 0.55 记为命中；
4. 连续 ≥3 帧命中才保留（抑制偶发误报），间隔 ≤8s 合并为窗口。

选左端盖而不是整条血条的原因：血条会随 Boss 掉血缩短，端盖形状固定；且端盖与等级无关，比「Lv.90」文字模板更泛化。

## 二、验证结果

| 视频 | 类型 | 采样 | 命中 | 误报/窗口 |
|---|---|---|---|---|
| Boss 实战（259s） | 正样本 | 519 | **492（94.8%）** | 单窗口 **1.0–252.5s** |
| P002 纳塔主线（1641s） | 负样本 | 1642 | **0** | 0 |
| P001 枫丹→纳塔（870s） | 负样本 | 870 | **0** | 0 |

正样本窗口覆盖整场战斗；两支剧情视频零误报。

## 三、接入项目 JSON

Boss 视频跑常规管线：**0 条对话事件**（战斗画面无字幕，符合预期）。

再用 `attach_combat.py` 写入战斗窗口：

```
{"windows": 1, "events_added": 2}
校验通过：events=2, by_action={fight_start:1, fight_end:1}, confidence 0.75
1.0   fight_start  inferred  0.75
252.5 fight_end    inferred  0.75
```

事件带证据帧（`data/frames/bili_boss_1080_combat/combat_*.jpg`），状态 `inferred`，置信度 0.75。

## 四、边界

1. **只覆盖顶部 Boss 血条**：普通敌人的头顶血条、伤害数字、技能 CD 未做；
2. 模板取自这支视频的 UI 比例（1080p），换分辨率需要重取模板或缩放；
3. 部分演出会隐藏血条，窗口可能被切成多段（用 gap≤8s 合并）；
4. 一场战斗只输出一对 fight_start/end，没有细分技能/闪避动作。

## 五、普通敌人（探索性探针，未完成）

在 57s 野外战斗片段（BV1EP411Y7VK）上试了「细小红条」检测：

- 红色横条长度 35–160 px、行数 ≥3 记为命中；
- 全片 114 采样命中 52（45.6%），窗口 **[15.5–45.0]**、[50.5–52.5]；
- 非战斗帧（t=2/8/14）为 0，战斗帧（t=20/26/38/44）为 5–8 行。

信号存在，但**没有人工标注真值**，无法给出 precision/recall；红特效、UI 红条都可能误报。因此只作为可行性探针，不算完成。
