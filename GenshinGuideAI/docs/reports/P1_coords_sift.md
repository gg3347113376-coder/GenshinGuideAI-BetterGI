# 坐标定位（SIFT）：真实视频跑通

- 日期：2026-11-07
- 工具：`tools/sift_localize.py`
- 数据：BetterGI 预计算 SIFT 特征（`Teyvat_0_2048_SIFT.kp.bin` + `.mat.png`）
- 验证视频：纳塔跑图 555s（1080p）

## 一、为什么换 SIFT

模板匹配（前一轮）对地图画风不鲁棒：粗匹配分数≈随机，坐标乱跳。
BetterGI 的主方案是 SIFT 特征匹配，旋转/尺度无关，且特征文件已随安装包提供。

## 二、特征格式（已解析）

| 文件 | 内容 |
|---|---|
| `Teyvat_0_2048_SIFT.kp.bin` | 681,139 个关键点 × 7 个 float32（x, y, size, angle, response, octave, class_id） |
| `Teyvat_0_2048_SIFT.mat.png` | 681,139 × 128 uint8 描述子 |

坐标换算（2048 级图像 → 游戏地图坐标）：

```
gameX = (32768 - x) / 2
gameY = (24576 - y) / 2
```

## 三、流程

1. 截取小地图（1920×1080 下中心约 (205,160)、直径约 300）并放大到 2px/单位；
2. 计算查询 SIFT（约 300–1000 个点）；
3. FLANN 匹配到 68 万地图描述子，Lowe ratio 0.75；
4. 剔除离群：匹配点中位数 + 散布 ≤450px；有上一帧时限制在 1200px 内；
5. 取匹配点中位坐标 → 游戏地图坐标。

## 四、结果（60–300s，每 10s 一帧）

- 成功 **23/25**（t=170、240 失败：运动模糊/切换瞬间匹配点不足）；
- 轨迹连续，全部落在纳塔区域（x 7732–7950，y -1638–-2234）；
- 相邻帧位移 8–140 单位/10s，符合跑图速度；
- 匹配点数 40–158，散布 130–240px。

样例轨迹：

```
t=60   (7731.8, -1637.8)
t=90   (7862.2, -1821.2)
t=120  (7756.3, -1902.9)
t=150  (7736.3, -2011.1)
t=180  (7905.8, -2144.7)
t=210  (7950.1, -2204.6)
t=270  (7917.6, -2139.5)
t=300  (7930.4, -2234.1)
```

## 五、接入协议

写入事件的 `position.map`：

- `x` / `y`：上面的游戏地图坐标；
- `layer`：`surface`（地表）；
- `method`：`minimap_sift`；
- `confidence`：按匹配点数与散布折算（建议 0.6–0.9）；
- `error_m`：暂填 null，等有真值再标定。

## 六、边界

1. 需要**已探索**小地图（迷雾区域无效，P002 即因此失败）；
2. 只覆盖地表；室内/地下需按层匹配；
3. 2px/单位与 300px 裁剪按 1080p UI 校准，换分辨率要重标定；
4. 快速移动/转场会偶发失败，需用上一帧位置做 ROI 或插值；
5. 目前只验证一支视频，尚未与任务距离做误差标定。

## 七、第二支视频泛化验证

同一套参数（中心 205,160 / 直径 300 / scale 2.0），不重新标定，换一支 435s 跑图视频（BV1u3xQemEKF）：

| 指标 | 结果 |
|---|---|
| 成功 | **8/13**（60–300s，每 20s） |
| 失败原因 | 匹配点散布过大（UI/地图界面） |
| 位置范围 | Natlan (8520,-2681) → Sumeru (4522,3606) → (-1568,2286) 等 |

位置跨区域跳变与视频中的传送/剪辑一致，不是匹配错误；说明算法可泛化，但**连续跟踪需要处理传送/镜头切换**（当前 `--no-roi` 逐帧独立匹配可绕过）。
