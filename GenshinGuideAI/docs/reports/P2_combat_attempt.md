# 战斗起止识别实验（未通过，如实记录）

- 工具：`tools/detect_combat.py`（实验性）
- 日期：2026-11-06
- 结论：**在当前样本上不可用**，未向项目写入任何战斗事件

## 一、尝试思路

1. 用队伍血条（底部中央 `Lv.90 10719/17816`）作为战斗信号；
2. 2 fps 采样，裁出血量数字区域，OCR 解析 `当前/上限`；
3. 血量下降 → 记掉血点；掉血点前后扩展合并成战斗窗口；
4. 输出 `fight_start` / `fight_end` 事件，`method=hp_drop_heuristic`，置信度 0.45。

## 二、实际结果

| 指标 | 数值 |
|---|---|
| 采样帧（2fps） | 3282 |
| 血条成功解析 | **38**（约 1.2%） |
| 检测到的掉血点 | 少且不成窗口 |
| 最终战斗窗口 | **0** |
| 写入事件 | 0 |

中间还发生过一次误报：557.5s 被判为战斗，实际是「获得新角色 卡齐娜」的抽卡/获得界面——说明允许弱信号时误报率很高。

## 三、失败原因

1. **HUD 大部分时间不可见**：这支视频 87% 是对话/过场，血条根本不在画面里；
2. **血量数字区域太窄**：裁紧后能读到 `10719 /17816`，但不同场景 UI 缩放/遮挡导致漏检；
3. **血条颜色校验不可靠**：血条是黄绿色（Hue 30–43），与背景橙色区分度低，绿色阈值会把所有帧挡掉；
4. **弱信号误报**：不校验 UI 语义时，任何带数字的界面都可能被当成血量。

## 四、下一步可行路线（按成本排序）

1. **敌人血条模板匹配**：截取敌人/首领血条的模板，匹配到才算战斗（需要先人工截模板）；
2. **伤害数字识别**：战斗时画面中央出现伤害数字，可用 OCR 数字 + 短时出现判定；
3. **技能图标 CD 状态**：检测技能图标变灰/读秒，作为战斗进行中的信号；
4. **人工标注 + 监督学习**：先标 100 张战斗/非战斗帧，再训练一个小分类器（需更多人工）。

## 五、建议

- 战斗识别暂不阻塞主线：方向一已覆盖地图/对话/交互；
- 若要继续，优先做「敌人血条模板匹配」，因为它误报最低、实现也直接。
