# P6 方向三：模拟环境闭环执行报告

- 场景数：6；每场景种子数：20
- 环境：20×20 网格，起点 (1,1)，目标 (15,15)，障碍墙 x=7（blocked/chaos）
- 执行器：A* 战术规划 + 执行反馈 + L1–L4 纠错 + 安全监督

| 场景 | 完成率 | 平均动作 | 平均重试 | 平均时钟 | 暂停次数 | L1 漂移 | L2 事件 |
|---|---|---|---|---|---|---|---|
| clean | 100% | 29.0 | 0.0 | 28.0 | 0 | 0 | 0 |
| drift | 100% | 29.7 | 5.2 | 28.7 | 0 | 128 | 0 |
| lost | 70% | 29.1 | 6.5 | 28.1 | 6 | 0 | 125 |
| timeout | 85% | 33.5 | 6.2 | 32.5 | 3 | 0 | 120 |
| blocked | 100% | 29.0 | 0.0 | 28.0 | 0 | 0 | 0 |
| chaos | 75% | 32.6 | 8.1 | 31.6 | 5 | 54 | 119 |

## 说明

- 完成率 = 两个步骤（移动 + 交互）都成功的比例；
- L1 漂移 = 位置偏移后的局部调整次数；L2 事件 = 动作丢失/阻塞后的本步重规划；
- 超时/失败超过重试上限会触发 L4 安全暂停（计入暂停次数）；
- 本报告只在模拟环境产生，**不代表真实游戏成功率**。

## 解读

- **clean / blocked / drift 均 100% 完成**：A* 能绕开静态墙，漂移由 L1 局部调整吸收（128 次）。
- **lost 70%、timeout 85%、chaos 75%**：未完成的运行全部触发 **L4 安全暂停**（连续失败超过每步 3 次上限），符合「禁止盲目循环、失败要交给人」的设计。
- 提高每步重试上限可提升完成率，但会放大盲目重试风险；当前取 3 是保守值。
- **只在模拟环境验证**，不代表真实游戏；真实环境需要方向一的坐标与方向二的导航网格。
## 战略层、检查点、审计与「视频→计划→执行」链路

- **战略层**：`Task` + `topological_order()`，支持依赖排序与环检测（有环直接报错）。
- **检查点**：每完成一个步骤写入 `runs/exec_checkpoint.json`（plan_index / tick / pos）；恢复时仍以重新观察为准。
- **审计日志**：每个动作一行 JSONL（`runs/exec_audit.jsonl`），可回放。
- **事件→计划**：`src/ggai/plan_builder.py` 把方向一事件转成示意计划（move→移动节点，dialogue/interact→节点交互）。
- **链路验证**（`tools/run_from_events.py`，P002 v7，前 12 条事件）：

```
events_used: 12   steps: 12
task_order: [t1, t2]
completed: true   steps_done: 12   actions: 20   retries: 0
checkpoint: {plan_index: 12, tick: 10, pos: [6, 6]}
audit_lines: 20
```

说明：节点坐标是示意位置，不是视频中的真实坐标；该链路证明「事件 JSON → 执行计划 → 受控执行 → 审计/检查点」是通的，不代表真实游戏可执行。
