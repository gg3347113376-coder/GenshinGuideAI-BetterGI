# 多 Seed 分支评估与 sim_runs 落库

- 工具：`tools/run_branches_multi.py`
- 存储：`src/ggai/simstore.py` → `runs/sim_runs.db`
- 测试：`tests/test_multi_seed.py`（3 个）

## 一、方法

4 个分支 × 20 个随机种子（0–19），同一初始状态（起点 1,1 / 目标 15,15）、同一规则版本 `rules-v1`：

| 分支 | 路线/环境 |
|---|---|
| A 直达 | (5,5)→(10,10)→(15,15) |
| B 南侧绕行 | (4,16)→(16,16)→(15,15) |
| C 直达+漂移 | 同 A，20% 位置漂移 |
| D 直达+动作丢失 | 同 A，20% 动作丢失 |

## 二、结果

| 分支 | 完成率 | 动作均值±标准差 | 重试均值 | 时钟均值 |
|---|---|---|---|---|
| 直达路线 | 100% | 31 ± 0.0 | 0 | 28 |
| 南侧绕行 | 100% | 35 ± 0.0 | 0 | 32 |
| 直达+漂移 | 100% | 32.65 ± 2.5 | 5.4 | 29.65 |
| 直达+动作丢失 | **70%** | 30.45 ± 12.64 | 6.25 | 27.9 |

优胜分支：**A 直达**（完成率 100%、动作均值最低）。

解读：
- 无故障分支完全确定（标准差 0）；
- 漂移只增加少量动作与重试，完成率不受影响；
- 动作丢失把完成率压到 70%，且动作数波动很大（12.64）——未完成的运行都触发了 L4 安全暂停。

## 三、落库

`runs/sim_runs.db` 共 **80 行**（每分支 20 行）：

```
by branch: A_direct 20 / B_detour 20 / C_drift 20 / D_lost 20
by status: completed 74 / paused 6
```

每条记录包含：

- `params`：分支 ID、节点序列、故障概率、修改说明；
- `rules_ver`、`seed`、`status`；
- `result`：动作数、重试、时钟、暂停原因。

这补上了协议里 `sim_runs` 表（仿真结果独立存储）的实际使用。

## 四、边界

- 仍是模拟网格环境，不是三维沙盘；
- 每分支 20 个种子，样本量有限；
- `exec_runs` 表仍未使用（真实/沙盘执行结果尚未归档）。
