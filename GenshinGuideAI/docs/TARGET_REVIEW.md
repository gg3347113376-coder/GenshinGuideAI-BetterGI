# 目标绑定与独立语义复核（协议 1.3）

此入口只处理本地攻略证据，不连接游戏窗口、抓取游戏画面、发送键鼠或投递 BetterGI 命令。`execution_allowed` 固定为 `false`，所有步骤仍为 `not_executed`。源视频来自攻略作者，不证明当前玩家状态。

## 目标绑定

`target_registry` 从已有 OCR、原转写和复听候选生成有证据引用的目标表，分开记录地区、锚点、神像、秘境、相对位置、宝箱、敌人和未知对象。任务模型只能选择已有 `target_id`，总目标也必须选择 `goal_target_id`。编译后保存总目标的 `goal_target_ref` 和步骤的 `target_ref`，动作参数里的描述由注册表提供，不能由模型另造一个名字。动作和目标类型的配对也写入结构约束；总目标说明、标题、意图说明和成功检查由动作目录与绑定目标生成，避免自由标题再次夹入错词。编译时补入注册目标本身的证据引用；模型原草案仍保留原始选择。

默认任务模型为本机 `qwen3.5:4b-q4_K_M`，规划与复核各使用新的请求，模型原始响应和精确 digest 均保存。当前使用关闭原生长推理的结构化调用，另一次复核负责审阅；本机实验中长推理出现重复自检直至截断，未采用其不完整结果。

这些 ID 表示本段攻略中有来源的候选描述，**不是已经定位的游戏实体 ID**。例如地区不能绑定到传送动作；“解说中的起点锚点”与“尚未定位的隐藏终点”分开；听不清的地形词保留原句，不自动登记成怪物。BetterGI 目录只提供同类型候选，即使仅剩一个也不确认坐标、地图层或玩家解锁状态。

只有解说明确要求回到、来到或传送到某处，才生成起点锚点候选；教程里提到一个锚点不等于要先传送。尚未定位的最终探索锚点不会进入传送动作的可选目标。

规则检查动作与目标类型、步骤与目标证据交集、参数描述一致性，以及未定位终点被当出发锚点等错误。不确定的实际身份保留 `null`；不以模型自评分替代证据。

## 独立复核

规划完成后进行另一次无对话历史的模型调用。复核输入只含待审目标/步骤和全部原始文字证据（包括被规划层排除的界面文字），不传规划器自评分、旧审核结论、规则错误提示或测试期望答案。OCR 位置分类明确标为可出错的提示。为适应本机上下文，重复字段压缩成带列名的行；原文和每条证据 ID 均保留。

复核器逐项判断最终目标、每个步骤和遗漏指令，并选择支持判断的证据 ID。程序直接从对应证据提取原文，不让模型重新抄写；原始模型选择与提取后的结果分别保存。每个步骤有固定的复核字段，不能重复审核一项后漏掉其他项。正面结论只能引用该步骤中合适的行动文字；常驻顶栏、作者图例和水印仍可用于指出误判，不能冒充正面依据。程序再次验证引用存在、引句确实来自对应原文、每个步骤恰好审查一次、支持证据属于该步骤，以及规则检查未报错。伪造引文、漏审、模型超时或输出截断不会得到可采用结论。计划、目标或来源发生修改，旧复核哈希随即失效；保存时还核对模型原始请求与回复。

当前规划和复核可使用同一模型权重。这是独立上下文中的第二次证据判断，**不是两个独立训练模型的交叉验证**，仍可能共同误判。最多根据问题重规划一次，二次仍有问题就保留拒绝结果。复核失败不无限重试。

- `supported_with_unknowns`：本轮语义和引用检查支持任务意图，但实际目标身份、路线等仍未知；待人工审阅，不能执行。
- `needs_review`：任务语义本身仍有疑点。
- `rejected`：发现无根据断言、错误绑定、遗漏或无效引文。
- `failed`：复核调用失败或输出不完整。

后三种状态的离线 CLI 返回 2，报告仍保留。返回 0 也不表示游戏任务成功。


输出目录必须是新的。`--review-only` 保留已有计划，只重做复核；`--recompile` 从已有计划引用的真实模型回复重新编译并复核。两者互斥。省略这两个选项才会重新调用规划模型生成任务。不会读取当前游戏窗口或发送键鼠。

反例测试将模型判断与规则拦截分开。只有针对注入错误本身的拒绝才计入拦截，不能拿基准计划原有的另一处错误充数。三段攻略是开发回归样本，不是独立随机评测；以本轮 `evaluation.json`、`counterexample-results.json`、`tests.json` 和原始请求/回复为结果依据。全部计划仍为未执行，具体锚点坐标、用户解锁状态及游戏内成功结果均未核实。

1.7 将正面引用限制前移至模型输出约束：`positive_support` 记录来源是否可作为正面依据；模型仍可判断不支持或不确定，但“支持”的引用只能从合格来源选择。界面文字仍可引用来解释拒绝。这个约束没有把模型结论事后改为支持，后置引文校验也保留。

早期从头重规划结果保留在本轮输出根目录和 `final-results`，其中额外传送、遗漏起点传送和引用误判保留为失败证据。`verified-results` 记录历史草案重编译；`fresh-results` 记录本轮三段重新规划；最终交付以 `delivery-results` 为准。各目录 `review-input.json` 分别标明 `new_plan`、`review_only` 或 `recompile_saved_draft`，不覆盖历史结论。


传送动作的输出约束进一步限制为有明确传送或起点返回指令的证据 ID，避免模型把介绍终点、解锁提示或背景地名选作传送指令。这个限制不确认锚点身份，也不证明当前玩家能传送。若模型完全漏写传送步骤的不确定性，编译器从已绑定目标的结构字段补齐身份、坐标及玩家解锁状态的未知说明；原始草案不改写。最终隐藏锚点修复只改变这一处说明，变更差异保存在 `hidden-repair-receipt.json`。
