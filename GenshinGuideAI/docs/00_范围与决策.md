# 范围与已确认决策（P0）

## 一、用户确认的六项决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 方向三「测试环境」 | **自建 Godot 沙盘 + 故障注入模拟器**；不做真实游戏自动化 |
| 2 | 3D 引擎 | **Godot 4** 做仿真回放；three.js 只做快速预览 |
| 3 | 样本视频 | 另选 20–40 分钟、含跑图+战斗+NPC 交互的片段，先跑通单视频闭环 |
| 4 | 模型 | 安装 **Ollama + qwen3-vl:4b**；OCR 用 PaddleOCR/Umi-OCR；ASR 用 faster-whisper |
| 5 | 首期范围 | **只做方向一 MVP**，不三线并行 |
| 6 | 复用 | 复用纳塔 OBJ 地形与攻略工作流资产；BetterGI 以独立进程调用（GPL-3.0，不并入代码库） |

## 二、本机环境核实

| 项 | 结果 |

| GPU | NVIDIA GeForce RTX 4060 Laptop，8 GB 显存（文档中“4050 Ti”已纠正） |
| Ollama / qwen3-vl:4b | **未安装**（文档假设已有，需补装） |

| 既有资产 | 纳塔 39 块地形 OBJ、106 份攻略工作流、faster-whisper small 模型 |

## 三、边界（不做）

- 不绕过反作弊、不注入、不改内存、不拦截未授权通信；
- 不在无授权的真实游戏环境做自动化；
- 不把沙盘验证结果冒充真机验证；
- 不把“字段校验通过”当作“任务已完成”。

## 四、优先级原则

1. 数据可信（方向一）优先于仿真正确（方向二），再优先于执行能力（方向三）；
2. 先协议、再管线、后界面；
3. 每期必须交付：源码、可运行版本、依赖说明、接口文档、样例数据、测试报告、已知限制。
