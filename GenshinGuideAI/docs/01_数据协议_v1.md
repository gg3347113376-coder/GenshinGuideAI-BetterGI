# 统一数据协议 v1

- 版本：`1.0.0`（`schema_version` 字段固定）
- JSON Schema：`schema/project_v1.schema.json`
- SQLite DDL：`schema/sqlite_v1.sql`
- 校验器：`python -m ggai validate <project.json>`

## 一、设计原则

1. **一条事件一条证据链**：`evidence` 必须能定位回视频时间戳/帧/OCR 框。
2. **未知即空**：坐标、高度、层级没有证据时写 `null` 并标 `method=unknown`，禁止估算后伪装成观测。
3. **四条时间轴分离**：`video_time`（视频时间）、`game_time`（游戏内时间）、`sim_time`（仿真时间）互不覆盖；`game_time`/`sim_time` 无数据时为 `null`。
4. **三类结果分开存**：本协议只承载「视频证据与提取结果」；沙盘结果（sim_runs）与授权环境结果（exec_runs）用独立表/文件。
5. **人工复核留痕**：`review` 记录状态、人、时间与修改差异，便于做回归样本。

## 二、实体

### Project（顶层）

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 固定 `"1.0.0"` |
| `project.id/name/created_at/description` | — | 项目元信息 |
| `project.model_versions` | object | OCR/ASR/VLM/规则版本，追溯用 |
| `sources` | array | 视频来源 |
| `segments` | array | 片段切分（跑图/战斗/交互/对话/过场） |
| `events` | array | 有序事件 |

### Source（视频）

`id`、`path`、`sha256`、`duration_s`、`fps`、`width`、`height`、`captured_at`、`notes`。

> 同一视频不同剪辑版本必须使用不同 `id`，禁止覆盖。

### Segment（片段）

`id`、`source_id`、`start_s`、`end_s`、`kind`（travel/combat/interaction/dialogue/cutscene/unknown）、`confidence`。

### Event（事件）

| 字段 | 说明 |
|---|---|
| `id` / `order` | 事件编号与排序 |
| `source_id` / `segment_id` | 来源与所属片段 |
| `video_time` | `{start_s,end_s,precision}`，precision ∈ frame/second/segment/unknown |
| `game_time` / `sim_time` | 可空；有则记录方法与精度 |
| `actor` | `{kind: player/npc/enemy/mechanism/unknown, name, confidence}` |
| `action` | `{type, params, method: observed/inferred/manual/unknown, notes}` |
| `position` | 见下 |
| `preconditions` | 字符串数组（任务状态、前置条件） |
| `expected_result` / `observed_result` | `{text, checks[]}` |
| `state_status` | observed / inferred / confirmed / unknown |
| `confidence` | 0–1 |
| `evidence` | 证据数组 |
| `review` | `{status: pending/confirmed/corrected/rejected, by, at, diff}` |

#### action.type 枚举

移动类：`move`、`teleport`、`climb`、`glide`、`jump`、`dodge`
战斗类：`normal_attack`、`charged_attack`、`plunge_attack`、`skill`、`burst`、`switch_character`、`fight_start`、`fight_end`
交互类：`interact`、`dialogue`、`dialogue_choice`、`pick`
其他：`wait`、`unknown`

> 关键区分：**看见动作 ≠ 知道按键**。只有画面能确认的写 `observed`；多证据推断写 `inferred`；人工确认写 `confirmed`；无法判断写 `unknown`。

#### position

```json
"position": {
  "map": {
    "x": null, "y": null,
    "layer": "surface|underground|cave|interior|instance|unknown",
    "region": "纳塔", "anchor": "话事处",
    "error_m": null,
    "method": "minimap|ocr|manual|map_data|unknown",
    "confidence": 0.0
  },
  "world": { "x": null, "y": null, "z": null, "error_m": null,
             "method": "minimap|manual|map_data|unknown", "confidence": 0.0 }
}
```

规则：
- `map` 与 `world` 是两套坐标，不能混用；
- 缺坐标时 `x/y/z=null`、`method=unknown`、`error_m=null`；
- 有坐标必须给 `method` 与 `confidence`；能估算误差就给 `error_m`；
- 地下/洞穴/独立场景必须用 `layer` 标出，禁止与地表路线强行相连。

#### evidence

```json
{ "kind": "ocr|frame|asr|map|manual", "t_s": 28.0,
  "path": "data/frames/demo_0028.jpg",
  "bbox": [430, 900, 1180, 40],
  "text": "我们来啦，玛薇卡……", "note": "对话字幕" }
```

## 三、校验与存储

```powershell
python -m ggai validate samples\sample_project.json   # 协议校验 + 摘要
python -m ggai import samples\sample_project.json runs\demo.db
python -m ggai stats runs\demo.db
python -m ggai export runs\demo.db runs\exported.json
```

- 入库前强制校验，校验失败拒绝导入；
- 导出后必须能通过同一套校验（有单元测试覆盖）；
- SQLite 中 `events` 平铺位置字段，`evidence`/`reviews` 独立表，便于查询与统计。

## 四、版本策略

- 字段只增不改语义；破坏性变更升 `schema_version` 主版本；
- 旧版本项目迁移用脚本，不直接改库；
- 任何新字段必须有文档与校验规则，不接受“临时字段”。
